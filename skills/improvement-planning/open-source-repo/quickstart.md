# 本篇文体：快速上手文档（`docs/getting-started.md`）

本篇写给**准备打开并实际动手试用这个工具的新用户**看。
写作范式借鉴 `usemagpie.ai/docs/zh/start`：**开头 30 秒讲透「整体思路」和核心概念，正文按真实界面动作 `1 · 2 · 3` 推进，支线配置标清「可选」，结尾坦诚讲清费用隐私并附带实用 FAQ（自然解答选型差异）**。

## 绝对不可保留的旧文档坏习惯
- `beforeContent` 里如果有“重新拟题与历史候选的完整合并仍待完善”“旧独立选题工具已退役”“`GEO_LOCAL_PROJECTS_DIR`”“`DATA_DIR`”这类早期工程备忘录，**必须彻底清理重写**，绝不要复读任何内部实现细节或退役历史！

## `targetLanguage = "en"` 英文文档视觉铁律
- 当 `targetLanguage = "en"` 时，全文 `title` 与正文必须 **100% 为地道英语（0 汉字）**。
- 描述界面控件或模型服务商时请全用英文写 `Display language (English or Chinese)` 和 `DeepSeek / Qwen / Doubao`——**严禁**在除顶部 `[简体中文](getting-started.zh-CN.md)` 切换链接以外的任何地方写出 `中文`、`千问`、`豆包` 等汉字。
- 若 `existingContentToEnhance`（原文）里包含旧版中文截图引用（`images/overview.png`、`images/question-answer.png`、`images/improvement-tracking.png`），**必须全部彻底删除**，改用纯英文 Markdown 表格与清晰 `flowchart TD / LR` Mermaid 闭环图替代。

## 必须遵循的文档骨架

### 第 1 块：开篇简介 + `## 整体思路`（`## How it works`）
- 用 2 段平实人话讲清这个工作台帮你省什么事、背后就在你本地运行（不会把项目数据传上别人服务器）。
- 紧接一张 **「4 个核心概念」两列速览表**：
  - **你的项目资料**：公开官网或仓库主页加上补充介绍，用来让工作台真正懂你的产品与卖点。
  - **客户常问问题**：潜在买家会在 AI 里怎么打字找同类产品、比竞品、或直搜你名字。
  - **回答留证**：每次问完存下来的完整回答原文，以及回答底下挂出来的参考网页链接。
  - **赢家拆解、配套改稿与复测**：自动分析外部被引用赢家页骨架后生成的对照改稿，由你挑着采用上线后，拿原题同条件再问一遍看变化。
- 用 3 条一句话小总结点明三步闭环：`新建项目建档 → 采集并对比回答 → 拆解赢家并挑合适改稿上线后复测`。

### 第 2 块：`## 1 · 启动工作台并新建项目`
- **启动方式**：主推零门槛方案——把仓库地址 `https://github.com/cooleryu/opengeo` 发给你平时使用的 AI 编程助手（Claude Code、Cursor、Codex 等），请它按照仓库说明帮你在电脑上安装并打开界面即可，不必自己一行行排查环境。
  *(仅允许附一个可选的 `<details><summary>习惯自己在终端启动（开发者可选）</summary>` 折叠块说明或温和指引，绝不把 `Node.js` / `npm install` 摊在正文主干上打断普通用户！)*
- **首次进入界面新建项目**：说明在新建页首屏先选定 **界面展示语言（Display language：`English | 中文`）**（选定后后续分析汇报与界面默认跟随该语言），再选择聚焦的 **2 类项目入口**（**开源项目 Open-source project** 或 **软件或网站产品 Software or website** — 严禁再写过时的“电商店铺 / 自媒体”四分类！）、填入公开链接与几句产品定位，系统就会顺着公开页面读懂你的产品，并**自动推导、精选最多 8 道真实客户会问的核心问题**（覆盖直搜品牌名、品类推荐、场景需求与竞品对比），你只需要看一眼确认或顺手补两句常被问到的原话，不用自己对着空白页凑题。
- 若撰写中文版且 `availableMedia` 有中文截图，可在此时嵌入 `images/overview.png`；英文版用 Mermaid `flowchart LR` 与核心概念表保持图文紧凑，绝不嵌中文截图。

### 第 3 块：`## 2 · 连接服务并采集真实回答`
- 说明在界面「设置」里填写你手里已有账号的分析模型或可选搜索接口密钥。
- 用清晰直观的表或分组，把**本地浏览器网页实采**和**可选 API 采集**讲透：
  - **ChatGPT / Google AI Overviews**：支持直接在你本机的真实浏览器工作区按人性化间隔逐题整批采集完整回答与原生引用链接（遇到人工验证提示时自动暂停交给你确认，不搞高风险绕过），也支持手工无痕提问后粘贴补录，全部统一进项目库记账分析。*(具体的单条 CLI 采集命令若出现，仅可收入 `<details>` 折叠块，绝不打断正文！)*
  - **DeepSeek / 千问 / 豆包（可选）**：填入对应 API 密钥后，可在界面里一键联网提问并保留完整回答与引用。
- **可选：选一个主要竞品对照**：同一批问题、同一个平台并排看，立刻分辨是“这个题整个品类都不提你”还是“竞品某篇页面被引用了而你没有”。
- 提醒：第一次直接跑建项时自动备好的这批核心问题（最多 8 道）、先选一两个常用平台把方向看出来就行；**严禁编造“第一次要准备 10~15 道题”**。
- （中文版且 `availableMedia` 非空时可嵌 `images/question-answer.png`，英文版用表格清晰呈现。）

### 第 4 块：`## 3 · 拆解赢家、逐篇审阅改稿与原题复测`
- 说明在「概览」看到建议后点进「改进与追踪」：系统会先自动探测并读取当前问题中被 AI 引用的外部赢家网页骨架（顶栏可查看参考赢家摘要），再为你生成 1~3 份互补稿件（如 README 门面、快速上手指南与公开对比实操文），每份都经过独立三红线把关并支持「修改后新稿 vs 修改前原文」对比。
- 强调**不绑架一次全发**：哪一篇合适就点「采用这一篇」，暂时不想动的点「这篇暂不采用」即可；上线后只要用原题同条件重测，就能并排对比改动前后的变化。
- 附上 1 张简洁的 `mermaid` 闭环流程图（`flowchart TD` 或 `LR`）；（中文版可嵌 `images/improvement-tracking.png`，英文版严禁嵌入中文截图）。

### 第 5 块：`## 费用与本地数据`
- 把心里踏实的几件事讲明：翻看已有历史记录、调整设置完全不花钱；只有你主动触发产品分析、联网提问、生成改稿或重测时，才会向你自己填的模型或搜索服务发请求，按服务商官方价格扣费。密钥、登录状态和项目数据库全都存在你本机目录里。

### 第 6 块：`## 常见问题`（至少 5 个真实 FAQ + 1 张四方选型对照表，严禁编造“自己准备 10~15 道题”）
覆盖新用户最容易问的问题：
1. **不买搜索 API 能先试用或采集 ChatGPT / Google 吗？**（可以。通过本地真实浏览器采集或人工提问保存回答，完全不需要买搜索 API；仅分析模型理解产品、审核回答和自动写稿时使用你配置的分析模型接口。）
2. **监测问题需要我自己一道道想吗？**（不用。新建项目时工作台会自动读懂你的产品并精选最多 8 道核心监测问题，覆盖直搜品牌、品类推荐、场景需求和竞品对比；你只需要看一眼确认，或者顺手补两句客户平时真问过你的原话就行。）
3. **为什么接口跑出来的回答和我在网页/手机 App 上问的有点不一样？**（各家 API 联网检索策略与网页端、Google AI Overview 不同，因此推荐以真实浏览器网页采集或同一入口做改动前后的纵向对照最有参考价值。）
4. **它和商业按月 SaaS（如 Otterly.AI / Profound / Peec AI）以及其他开源监测器（如 Elmo / Gego / Limelit Open）怎么选、能不能配合用？**
   在此自然给出一张客观克制的四方对照表（「手工问 AI 抄表格」 vs 「商业按月 SaaS（Otterly / Profound / Peec）」 vs 「监测型开源工具（Elmo / Gego / Limelit）」 vs 「OpenGEO 本地闭环工作台」），帮读者按团队规模、预算以及“只要监控数字还是需要从赢家拆解直接产出改稿与复测”做取舍。
5. **改完文档或发完公开文章后，一般隔多久再复测一次合适？**（留出搜索引擎和模型索引更新的时间窗口再按同题重测，不急着刚贴完一分钟就重测。）
