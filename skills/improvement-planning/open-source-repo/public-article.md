# 本篇文体：对外公开获客实操长文（介绍与实用对比）

本篇写给**手上有网站、独立软件、产品服务或开源项目、正关心“用户在 ChatGPT、DeepSeek、Google 或豆包里问选型时，AI 到底有没有推荐我”的真实产品人与开发者（未来会用得上的潜在用户）**，而不是写给同行看技术踩坑日记。

## 写作要求

1. **黄金前三段立住紧迫感，零说教开头**
   - **第 1 段**：直接切入买家真实提问场景——当潜在用户问 ChatGPT 或 Google AI 推荐哪款同类工具时，回答里往往只给出 2~3 个竞品名字和官网链接。
   - **第 2 段（对手替代焦虑）**：用 1~2 句直白的话点明风险——你以为别人搜同类方案会顺便看到你的项目，实际却是竞争对手正在替 AI 回答“什么工具最好用”，而你的页面连引用候选都进不去。
   - **第 3 段**：立刻给出“怎样查出 AI 到底信了谁的页面、再按缺口补齐结构”的 3 步实操路线。
   - 严禁“用自己老账号搜自己有记忆幻觉”等居高临下常识科普，严禁写成“我们怎么给自己修 bug、盘点同名软件”的内部日记。

2. **用真实横评、提问式 H2 与实用对照表做出「想收藏」的价值**
   - 尽量参照输入中的 `referenceWinners`（被 AI 实际引用的外部赢家标题骨架与开篇逻辑），用读者会直接问的问题作 `##` 标题，每节前两句直接给出自洽结论。
   - 客观对比不同定位的方案（如商业 SaaS **Otterly.AI / Profound / Peec AI**、偏监测跟踪的开源工具 **Elmo / Gego / Limelit Open** 与定位完整优化闭环的本地开源工作台 **OpenGEO**），讲清各自适合谁、采集方式、数据放哪、以及“只看监控数字/引用”与“真实浏览器采集 → 赢家页面骨架拆解 → 直接生成与审核改稿 → 原题复测”的区别，绝不贬低或拉踩任何竞品或商业产品。
   - 配 1 张清晰的选型对照表与简明流程图，让现在没时间立刻折腾的读者也愿意收藏。

3. **视觉纯净与零门槛启动**
   - 当撰写英文公开文章（`targetLanguage = "en"`）时，**绝不嵌入中文 UI 截图**（`docs/images/*.png`），用纯英文 Markdown 表格和 Mermaid 流程图代替；若撰写中文文章且 `availableMedia` 非空，再按实际路径自然配图。
   - 结尾附上项目真实入口（如 `https://github.com/cooleryu/opengeo`），引导读者把仓库地址发给自己的 AI 编程助手（Claude Code、Cursor、Codex 等）帮忙在本地启动，不堆 `git clone` / `npm install` 命令墙。
