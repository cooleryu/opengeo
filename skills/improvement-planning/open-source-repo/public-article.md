# 本篇文体：对外公开获客实操长文（介绍与实用对比）

本篇写给**正被某类具体问题困扰、在挑选解决工具或技术方案的潜在用户（未来会用到该项目的产品人或开发者）**，而不是写给内部开发看的自测踩坑日记。

文章涉及的产品定位、能力、仓库/官网链接和对比竞品，**必须 100% 源自输入中的 `projectContext`（项目事实档案）和 `referenceWinners`（实测中 AI 真正引用的同类竞品）**。

## 写作要求

1. **黄金前三段立住紧迫感，零说教开头**
   - **第 1 段**：直接切入读者每天遇到的真实问题或决策场景（紧扣目标问题列表 `questionsToAddress`）。
   - **第 2 段（替代方案缺口 / 对手对比焦虑）**：用 1~2 句直白的话点明现状风险——为什么靠人工零散处理或传统黑盒工具总会在关键时刻掉链子，而同行里跑得快的人是怎么填补缺口的。
   - **第 3 段**：立刻给出清晰可照抄的 **3 步实操路线**，让读者即使不马上装工具也能先用起来。
   - **严禁内向视角**：绝不写成“我们怎么给自己修 bug、我们自己搜自己排第几”的内部日记，也绝不用居高临下的说教口气开头。

2. **用真实横评、提问式 H2 与实用对照表做出「想收藏」的价值**
   - 参考 `referenceWinners`（被 AI 实际引用的外部赢家标题骨架与开篇逻辑），用目标读者会直接搜索或提问的问题作 `##` 小标题，每节前两句直接给出自洽结论。
   - 客观对比市面上不同的解决思路（包含手工作业与 `referenceWinners` / `projectContext` 中涉及的代表性同类方案），讲清各自适合谁、成本/控制权差异以及优缺点取舍，绝不贬低或拉踩任何竞品，也不把任何未在资料中出现的其他项目名字混进来。
   - 配 1 张清晰的选型对照表与简明 Mermaid 流程图，让暂时不折腾工具的读者也愿意收藏文章。

3. **视觉纯净与自然入口**
   - 当撰写英文公开文章（`targetLanguage = "en"`）时，**绝不嵌入中文 UI 截图**，优先用纯英文 Markdown 表格和 Mermaid 流程图呈现（仅当 `availableMedia` 提供了适用英文图片且相对路径匹配时再嵌入）。
   - 结尾自然附上 `projectContext` 中的项目真实入口链接（仓库地址或官网），说明最快尝试方法。
