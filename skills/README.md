# 按页面找 Agent

从左侧页面名称进入，找到要调整的功能，再打开它的提示词或参数。业务主线仍是：理解产品与内容 → 确认问题 → 搜索诊断 → 方案与审核 → 跟测学习。

| 左侧页面 | 要调整什么 | 文件入口 |
| --- | --- | --- |
| 概览 | 提及率、引用率与竞品推荐小卡 | [概览](pages/概览.md) |
| 问题监测 | 生成问题、审核问题、分析搜索回答 | [问题监测](pages/问题监测.md) |
| 竞品对照 | 推荐对标对象、解释差距和机会 | [竞品对照](pages/竞品对照.md) |
| 流量数据 | 访问数据的读取与统计 | [流量数据](pages/流量数据.md) |
| 内容资产 | 理解产品、调查已有文章和研究 | [内容资产](pages/内容资产.md) |
| 改进与跟踪 | 诊断、生成方案、独立审核、修订与跟测 | [改进与跟踪](pages/改进与跟踪.md) |

## 调整哪种文件

- **判断标准和表达**：改对应的 `.md` 提示词。阶段型 Skill 的 `SKILL.md` 是导航，模型只收到该阶段需要的正文。
- **推荐数量、输出长度、温度、超时、材料预算、默认轮数**：改对应 `parameters.json` 中已有的字段。应用调用时读取并校验，不是另存一份说明。JSON 沿用项目现有能力，无新增解析依赖。
- **模型与思考强度**：继续在应用「设置 → 分析 Agent」中调整。各页注明使用 ChatGPT 订阅还是 API 模型的现有选择规则；本次没有统一切换模型。
- **工具与循环**：各页链接实际执行入口。应用内这些分析 Agent 使用给定材料，没有开放工具循环；独立仓库调查 Workflow 的网页能力和阶段循环另有明确入口。不要把尚未实现的工具写成可用配置。
- **返回字段、引用校验、质量门槛**：仍由相应程序约束，各页给出位置。调整提示词不代表可以取消这些要求。

概览与竞品页共用[竞品推荐标准](competitor-analysis/SKILL.md)，不各写一套。推荐出场条件与表达维护在该提示词，推荐数量维护在同目录参数；页面入口同时链接执行校验、展示组件和接口文档，便于一起核对。

## 生效与状态

应用内出题、回答分析、竞品分析和改进流程，已通过 [统一读取器](../src/lib/geo/agent-files.ts) 在调用时读取提示词和参数。只读取当前阶段，不把本目录或其他 Agent 的说明一起送入模型。原有模型配置、任务已保存的执行条件继续按各调用方的优先级生效；编辑提示词不会自动重跑已有结果。

仓库调查选题仍是应用外的独立 Workflow，保留原路径、阶段提示和运行配置。六个页面是维护导航，不是六个都已实现的独立 Agent，也不会在进入页面时自动启动所有 Agent。

凭证继续由本地连接管理；这里的文件不得写入 API Key、登录 Token 或个人账号信息。底座通用聊天的 `src/lib/prompts/` 不属于本次 OpenGEO 页面 Agent 整理范围。
