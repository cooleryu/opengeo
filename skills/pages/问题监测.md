## 回答分析

**状态：搜索后自动执行，结果供本页和概览使用。** 例如回答“我不知道 Example Project”，应判断未识别项目，不能仅因出现名字就算提及。

| 调整内容 | 文件 |
| --- | --- |
| 是否正确识别品牌、是否原生引用自有内容 | [回答分析 Skill](../answer-evidence-review/SKILL.md) |
| 输入字节上限、超时、温度、输出上限 | [parameters.json](../answer-evidence-review/parameters.json) |
| 必填字段、原文证据校验、模型选择 | [answer-audit.ts](../../src/lib/geo/answer-audit.ts) |
| 搜索后何时调用 | [research-collection.ts](../../src/lib/geo/research-collection.ts) |
| 判断怎样保存 | [answer-audit-store.ts](../../src/lib/geo/answer-audit-store.ts) |

启用 ChatGPT 订阅分析时，使用设置中选择的订阅模型和思考强度；未启用时使用现有 API 模型。单次分析不开放外部工具、不自动重试；失败仍保存为待核实。搜索服务由搜索设置单独控制。

## 从 GitHub 入口调查后再出题

**状态：独立 Workflow，尚未与本页应用内出题统一。** 不把两个入口当成同一套规则。

- 先理解产品和文章：[内容资产](内容资产.md)。
- 调查完如何出题：[propose.md](../repository-topic-discovery/prompts/propose.md)。
- 独立审题：[review.md](../repository-topic-discovery/prompts/review.md)；修订：[repair.md](../repository-topic-discovery/prompts/repair.md)。
- 工具、阶段顺序和超时：[独立 Workflow](../repository-topic-discovery/references/workflow.md)。

本次整理只统一查找入口和应用内文件读取，没有把独立 CLI 流程接进页面，也没有改变两套流程原有的判断标准。
