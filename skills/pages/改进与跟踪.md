## 项目整体优化

**状态：已有应用调用，等待真实模型运行验证。** 从概览选择重点优化或深度优化，冻结当前批次的全部问题、已有原始回答与自有内容，合并共同缺口为一份整体行动方案。重点最多 3 项，深度最多 8 项并提供更多材料；两者质量标准相同。

| 调整内容 | 文件 |
| --- | --- |
| 整体方案与合并行动 | [project-propose.md](../improvement-planning/project-propose.md) |
| 独立审核 | [project-review.md](../improvement-planning/project-review.md) |
| 根据上一轮候选与审核意见修订 | [project-repair.md](../improvement-planning/project-repair.md) |
| 项目优化轮数与模型输出参数 | [parameters.json](../improvement-planning/parameters.json) 中的 `projectOptimization` |
| 冻结范围、材料预算、引用校验与统一质量门槛 | [project-optimization.ts](../../src/lib/geo/project-optimization.ts) |
| 保存、并发去重及失败重试 | [store.ts](../../src/lib/geo/store.ts) |

按初始化、准备改动、独立审核、必要时修订和复审推进，默认最多 2 轮，硬上限同为 2 轮（最多 4 次模型调用），不重新搜索。每个阶段写入现有任务，审核前先保存候选；每轮候选、审核意见和修订历史可回看。缺少原始证据或未形成行动时明确停止；修订没有实质变化时保留候选并停止，不反复审核同稿碰运气。支持核验的原始记录沿用已有读取器；缺失或不支持的记录显式列为限制。每项四维评分均至少 70、平均至少 80，并通过原始目标和真实依据硬检查，才可交用户审阅。失败或未知不能算通过；独立复审只接收原材料与新候选，不接收历史评分。内部审核不代表已实施或有效。尚未接入项目整体方案的确认实施、自动发布或跟测。

模型材料按 UTF-8 字节分池：重点模式回答 56 KiB、自有正文 32 KiB；深度模式回答 176 KiB、自有正文 64 KiB。回答预算均分给全部冻结问题，再分给该题记录；自有正文单独分配。未提供内容逐项记录实际字节数和原因，不从范围中删除原题。失败或服务重启中断保留已保存成果，不标成完成。失败或未通过审核后，用户可明确按原快照重试（再次调用模型，不刷新证据，保留之前各轮记录），也可归档后用最新材料新建任务。归档只代表关闭任务，不代表已实施或有效。
