# 调查并理解项目

应用内新建项目使用此 Agent：读取用户给出的公开入口，主动补找必要资料，保存原文及其与能力、贡献和需求的关联，再交给现有理解、选题与独立审核流程。

- 补找资料：[discover.md](discover.md)；资料关联：[relations.md](relations.md)；理解摘要：[understand.md](understand.md)。每一步只读取对应提示。
- 读取预算、模型超时与返回长度：[parameters.json](parameters.json)。由应用读取并校验。
- 运行入口：`src/lib/geo/project-onboarding-analysis.ts`；公开读取：`src/lib/geo/project-public-source.ts`。

入口可选开源仓库、电商、公司或创作者。GitHub 优先读取公开 README，再尝试最多两个 README 链接的相关文档；其他入口读取公开页面。要求登录、访问验证、非公开网络地址或无法提取正文时，明确失败，不尝试绕过限制。

若本机 DNS 全部返回 `198.18.0.0/15` 代理占位地址，使用固定公共 DNS，必要时用固定可信 HTTPS DNS 确认真实公开地址。不会连接占位地址；每次跳转继续验证，并将已验证的 IP 固定到实际连接。普通内网地址不会触发此兼容处理。

分析沿用设置中的分析 Agent：启用 ChatGPT 订阅时使用其选定模型及思考强度，否则使用已保存 API 模型。补充调查最多两轮、四次额外页面读取、一次公开需求搜索；仅可读取实际页面中的链接或搜索返回的链接。外部搜索复用已配置的 DeepSeek 搜索接口，未配置时沿现有链接读取并记录限制；分析与搜索可能收费，失败不跨供应商重试。此处的需求调查不写入品牌可见性记录。

原文、逐字引用、资料关联和搜索费用状态自动追加到当前项目 `db.sqlite` 的 `geo_project_research_runs/sources/relations` 三表；内容资产和选题从 SQLite 读取最新批次。每次成功读取即保存，失败不覆盖旧记录；另保留原文文件供查阅。项目目录及理解摘要仍沿用现有本地项目目录结构。修订理解复用已保存资料，不重新调查。

理解完成后自动接当前 `question-planning` 流程，沿用现行选题规则；旧独立 Python 选题工具退役，旧运行资料保留。此流程不会启动可见性测量或发布。
